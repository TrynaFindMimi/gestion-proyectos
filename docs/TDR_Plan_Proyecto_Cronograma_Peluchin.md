### METODOLOGÍA DE TRABAJO — SCRUM + KANBAN

El proyecto se gestiona con una metodología híbrida que combina **Scrum** (para la planificación por sprints y entregables) y **Kanban** (para la visualización y control del flujo de trabajo diario).

#### Marco Scrum

| Elemento | Configuración del proyecto |
|----------|----------------------------|
| Sprints | 4 sprints de 2 semanas (8 semanas de desarrollo) |
| Artefactos | Product Backlog, Sprint Backlog, Incremento del producto (demo funcional) |
| Ceremonias | Planificación de sprint, Daily (seguimiento), Demo funcional, Retrospectiva (§Reuniones programadas) |
| Roles | Product Owner (responsable del albergue), Scrum Master (Santiago Acha), Equipo de desarrollo |
| Entregables | E1–E11 asociados a sprints (§Entregables) |

#### Marco Kanban

| Elemento | Configuración del proyecto |
|----------|----------------------------|
| Tablero | Columnas: Backlog → Por hacer → En curso → En revisión → Hecho |
| Gestión de tareas | Trello / Jira / Notion (§Herramientas) |
| Límite de trabajo en curso (WIP) | 1–2 tareas por persona para evitar cuellos de botella |
| Control del flujo | Revisión diaria del tablero y desbloqueo de impedimentos en el Daily |
| Gestión de cambios de alcance | Las nuevas tareas entran al Backlog; si son ampliaciones de alcance requieren adenda al contrato |
| Dependencias del albergue | Se registran como tareas bloqueadas en el tablero (§Dependencias) |
